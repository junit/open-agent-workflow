# Background

Agent hosts can load several independent engineering Skill collections. Each
collection may provide planning, implementation, testing, review, or
verification instructions. Without a shared rule, triggers can compete and
the model may change methods mid-deliverable.

OAW addresses that problem with one portable Policy Set and named Profiles.
The Policy states the boundaries; a Profile names the method; the model
resolves readable Skills at the moment each Responsibility becomes current.
This keeps arbitration in readable rules instead of a hidden executable.

OAW also installs thin native instruction entrypoints for multiple hosts. The
entrypoints point to the same Policy Set while retaining each host's format,
scope, and reload behavior. The installer owns only those files and its
private bookkeeping.

The Host remains the execution authority. OAW does not emulate a model,
start child processes, or promise physical containment. Optional Machine
Assurance and Bridge features can add evidence without becoming prerequisites.
